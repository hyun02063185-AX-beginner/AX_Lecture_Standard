# AX Lecture Copy Style Guide v0.1

## Purpose

작성자의 원고체 메모를, 학습자가 슬라이드를 보며 자연스럽게 따라갈 수 있는 강의 화법으로 옮기기 위한 재사용 가능한 원칙이다. 이 문서는 `AI_Attitude` Copy Polish Sprint(`docs/18_ai_attitude_copy_polish_review.md`, AI_Attitude 저장소)에서 실제로 검증된 판단 기준만 일반화한 것이며, 특정 강의의 문구·제목·이미지 설명은 포함하지 않는다.

강사의 개인 경험·경력·사례·의견·판단은 [Instructor Grounding & Audience-Aware Lecture Voice](16_instructor_grounding_and_audience_voice_v0.1.md)를 먼저 따른다. 이 Guide는 확인된 내용의 표현을 다루며, 강사의 관점을 만들거나 바꾸는 기준이 아니다.

## Voice preserves the instructor

자연스러운 강의 화법은 강사의 실제 관점과 경험, 콘텐츠의 사실을 유지한 상태에서 청중이 이해하기 쉬운 문장으로 바꾸는 일이다. AI는 강사의 관점을 만들어내지 않는다. 제공되거나 확인된 Source가 없는 개인 경험을 `제가 해보니` 같은 1인칭 화법으로 쓰지 않으며, 업계 일반 사례나 AI의 판단을 강사 개인의 사례·판단으로 바꾸지 않는다.

수강생, 선수지식, 수강 목적, 강의 후 할 수 있어야 할 일이 화법에 영향을 주는데 불명확한 경우에만 Audience Context를 확인한다. 이미 충분히 알려진 정보는 다시 묻지 않는다.

## Three language layers

- **Knowledge Language**: 객관적·관계 중심의 구조화 언어. 짧은 명사 표현을 허용한다.
- **Lecture Language**: 실제 강사가 청중에게 말할 수 있는 문장. Audience에 따라 용어 풀이, 질문, 비교, 사례의 난이도를 조절한다.
- **Slide Language**: 화면에서 설명을 보조하는 더 짧은 언어. 핵심 질문·문장·시각적 단서로 쓰며 강사의 설명을 대체하지 않는다.

이 Guide의 Spoken Naturalness는 주로 Lecture Language와 Slide Language를 다룬다. 표현을 변환해도 Knowledge의 사실관계와 Grounded 관점은 임의로 변경하지 않는다.

## 판정 기준 하나

> **강사가 이 문장을 강의실에서 그대로 말해도 어색하지 않은가?**

체크리스트가 아니라 이 질문 하나로 모든 판단을 내린다. 아래 원칙들은 이 질문에 답하기 위한 세부 기준일 뿐이다.

## Reader First

작성자의 생각을 정리한 메모가 아니라, 학습자가 화면을 보면서 읽는 문장으로 쓴다. 저자 중심 서술("이 강의는 ~을 다룬다")보다 독자가 따라갈 수 있는 설명("~부터 정합니다")을 우선한다.

## Spoken Naturalness

기본 화법은 자연스러운 존댓말 설명체다. 다음 패턴은 실제 대화에서 거의 쓰이지 않으므로 피한다.

- **추상명사 + 정의문**: "OO은 △△의 기준점이다" 같은 사전적 정의 문장. 추상명사가 주어이고 "이다"로 끝나는 선언문은 특히 의심한다.
- **문어체 비유 단어**: "잣대"처럼 글에서만 쓰고 말할 때는 거의 쓰지 않는 단어.
- **번역투**: `~을 통해`, `~에 대한 이해`, `~을 기반으로`, `~의 관점에서`, `~을 가능하게 한다`.
- **억지 은유**: 이미지나 문맥과 강하게 연결되지 않는 은유. 은유 자체가 나쁜 것이 아니라, 근거 없이 붙은 은유가 문제다.
- **과도한 대구**: "AI는 실행하고, 사람은 판단한다" 같은 대구 문장은 정말 기억시킬 핵심 장면에서만, 강의 전체에서 드물게 사용한다.

이 패턴들은 제목보다 **본문·캡션**에서 특히 조심한다. 제목은 짧은 headline 성격을 가질 수 있어 원칙을 다르게 적용한다 — 아래 "제목과 본문은 다른 규칙" 참고.

## Concrete Verbs

추상명사보다 구체적 행동 동사를 우선한다 — 정한다, 확인한다, 남긴다, 비교한다, 물어본다, 눌러본다, 적어둔다, 검토한다, 좁힌다 같은 동사는 그 자체로 화자의 행동을 드러내 자연스럽게 읽힌다. 제목이 동사 하나로 끝나면 대개 이미 자연스럽다; 명사만으로 끝나는 제목("OO의 △△")은 다시 검토한다.

## 제목과 본문은 다른 규칙

Web Deck 제목은 큰 headline 타이포그래피로 표시되는 경우가 많아 완전한 문장보다 짧은 구가 자연스러울 수 있다. 제목을 고칠 때는:

- 동사 중심의 짧은 구(예: "~한다", "~해본다")로 만들거나,
- 본문이 답하게 될 짧은 질문으로 만든다.

전체 문장을 제목에 욱여넣지 않는다 — 길어진 제목이 headline 레이아웃에서 줄바꿈되거나 넘치면 그 자체로 결함이다. 완전한 설명은 캡션·본문에 맡긴다.

## Image + Copy

이미지가 있는 슬라이드는 Image와 Text를 하나의 장면으로 판단한다. 이미지가 이미 보여주는 내용을 텍스트로 반복하지 않는다. 다음 관계 중 하나로 역할을 나눈다.

- Image = 상황 / Text = 의미
- Image = 비유 / Text = 실제 행동
- Image = 문제 / Text = 해결
- Image = 결과 / Text = 확인할 질문

## Copy Density

화면을 원고처럼 채우지 않는다. 슬라이드 대부분(80~90% 수준)은 자연스러운 설명 화법이고, 일부만 기억시키는 Key Copy로 압축한다. 모든 슬라이드가 명언처럼 보이면 실패다.

## Key Copy Restraint

Opening, Section Transition, Key Message, Closing처럼 지정된 장면에서만 조금 더 압축된 카피를 허용한다. 이런 예외 장면에서도 추상명사 정의문("OO은 △△이다")은 피한다 — 압축된 문장이라도 사람이 실제로 할 법한 말이어야 한다.

## Opening / Closing Callback

Opening에서 던진 질문이나 재료를 Closing에서 반드시 회수한다. Closing에서 새로운 개념을 추가하지 않는다. 이 원칙은 [Authoring Guide](05_web_deck_authoring_guide.md)의 Opening → Closing Callback과 동일하며, Copy Style Guide는 그 회수를 "화법" 차원에서 재확인한다.

## Self Review

수정을 마친 뒤 전체 사용자 노출 문장에서 다음을 한 번 더 찾는다: 추상명사 남용, 대구 남용, 과도한 은유, 번역투, 비슷한 문장 구조 반복, 이유 없는 슬로건. 발견되면 사람이 실제로 쓰는 표현으로 다시 쓴다. 이때 자연스러움을 이유로 강사의 관점·판단 강도·경험 범위·사실관계를 바꾸지 않는다.

## Not in this Guide

다음은 이 문서에 포함하지 않는다 — Authoring Rule이지 Engine 기능이 아니기 때문이다.

- 특정 강의의 실제 문구, 제목, 이미지 설명
- 특정 Key Copy 예시(예: 특정 슬라이드의 마무리 문장)
- Template 소스 코드에 강제로 심는 문구나 placeholder 카피

Web Deck Template과 Lecture Experience Template의 `starter/` 소스에는 이 Guide의 문구를 하드코딩하지 않는다. 이 문서는 저자가 자신의 콘텐츠를 검토할 때 참고하는 Authoring Rule이다.
